Tailscale Configuration Guide

VPS-1 is the public reverse proxy. VPS-2 through VPS-N run websites or private services. Every server and client signs in to the same Tailscale tailnet.

Internet → VPS-1 (rpctl, Nginx, SSL, Tailscale)
                    ↓ encrypted Tailscale network
          VPS-2 100.x.x.x · VPS-3 100.x.x.x · mobile devices
Control access in your tailnet policy. Only approved users and devices should be allowed to reach private web services.

Step 1 — Install VPS-1

Use a clean Ubuntu Server 22.04 LTS or 24.04 LTS VPS with a public IPv4 address. Allow SSH and TCP ports 80 and 443 in the provider firewall.

sudo apt update
sudo apt install -y git
git clone https://github.com/hgn389/Reverser-Proxy-WireGuard-Tunnel.git rpctl
cd rpctl
sudo bash scripts/install.sh

Select Tailscale as the VPN backend. The installer installs the official stable package, starts tailscaled, and displays a login URL. Complete the login before continuing.

sudo rpctl status
sudo rpctl tailscale status
tailscale ip -4

Step 2 — Add VPS-2 Through VPS-N

Install Tailscale on every upstream server and sign in to the same tailnet. Follow the official Linux installation instructions for that server, then verify its address:

curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up
tailscale ip -4
tailscale status

When device approval is enabled, approve the server in the Tailscale Admin Console. Apply grants or ACLs that allow VPS-1 to reach the required application ports.

Step 3 — Prepare and Test the Website

Run the website on the upstream server and make it listen on its Tailscale address or 0.0.0.0. Use the real address returned by tailscale ip -4.

# Run on VPS-1 and replace the example address
ping -c 4 100.101.102.103
curl -I -H 'Host: shop.example.com' http://100.101.102.103:80

The HTTP request should normally return 200, 301, or 302 before the reverse proxy is created.

Step 4 — Add DNS, Reverse Proxy, and SSL

  1. Create an A record for shop.example.com pointing to the public IPv4 address of VPS-1.
  2. Open Dashboard and add shop.example.com.
  3. Use the upstream device's Tailscale address, such as http://100.101.102.103:80, or its MagicDNS name.
  4. After DNS reaches VPS-1, issue the SSL certificate in the Reverse proxies section.

Public traffic terminates at VPS-1. The connection from VPS-1 to the upstream server travels through Tailscale.

Connect a Computer or Mobile Device

  1. Install the official Tailscale application on Windows, macOS, iOS, or Android.
  2. Sign in to the same tailnet used by VPS-1.
  3. Approve the device when tailnet device approval is enabled.
  4. Confirm that the tailnet policy allows the device to reach the intended server and port.
  5. Open the private service through its Tailscale IP or MagicDNS name.

Tailscale does not use the WireGuard peer configuration files or QR codes shown in WireGuard mode.

Common Problems

  • Device is missing: confirm that it signed in to the same tailnet and was approved.
  • Ping or HTTP is blocked: review the tailnet grants or ACLs and the upstream server firewall.
  • 502 Bad Gateway: VPS-1 cannot reach the configured upstream address and port.
  • SSL cannot renew: keep public DNS pointed to VPS-1 and port 80 reachable for the HTTP-01 challenge.

sudo rpctl tailscale status
tailscale netcheck
sudo rpctl system nginx-test

Configuration Guide

VPS-1 is the public reverse proxy. VPS-2 through VPS-N run websites or private services. Each server or device that joins WireGuard must use its own peer configuration.

Internet → VPS-1 (rpctl, Nginx, SSL, WireGuard 10.10.10.1)
                    ↓ encrypted WireGuard tunnel
          VPS-2 10.10.10.2 · VPS-3 10.10.10.3 · VPS-N
Keep every client configuration private. It contains a WireGuard private key. Never reuse one configuration on two devices.

Step 1 — Install VPS-1

Use a clean Ubuntu Server 22.04 LTS or 24.04 LTS VPS with a public IPv4 address. Allow SSH, TCP ports 80 and 443, and UDP port 51820 in the provider firewall.

sudo apt update
sudo apt install -y git
git clone https://github.com/hgn389/Reverser-Proxy-WireGuard-Tunnel.git rpctl
cd rpctl
sudo bash scripts/install.sh

Select WireGuard private mode, choose the default 10.10.10.0/24 subnet, and select acme.sh. The installer creates VPS-1 as 10.10.10.1 and the first client as 10.10.10.2. For independent rpctl servers, select a different private subnet for each installation, such as 10.20.0.0/24 and 10.30.0.0/24.

sudo rpctl status
sudo rpctl wg peer list
sudo rp

The first client file is:

/etc/rpctl/wireguard/peers/client1.conf

Step 2 — Copy client1.conf to VPS-2

Copy client1.conf from VPS-1 to /root/client1.conf on VPS-2. You may use SCP, SFTP, or WinSCP. Delete temporary copies after installation.

Example with SCP, run from a trusted computer that can reach both servers:

scp root@VPS1_PUBLIC_IP:/etc/rpctl/wireguard/peers/client1.conf ./client1.conf
scp ./client1.conf root@VPS2_IP:/root/client1.conf

Step 3 — Install WireGuard on VPS-2 or Orange Pi

Run on VPS-2. Ubuntu, Debian, and Armbian use the same commands:

sudo apt update
sudo apt install -y --no-install-recommends wireguard-tools
sudo install -d -m 700 /etc/wireguard
sudo install -m 600 /root/client1.conf /etc/wireguard/wg0.conf
sudo systemctl enable --now wg-quick@wg0
sudo rm -f /root/client1.conf

Verify the interface and tunnel on VPS-2:

ip address show wg0
sudo wg show
ping -c 4 10.10.10.1

Verify VPS-2 from VPS-1:

ping -c 4 10.10.10.2
sudo wg show

A recent handshake and successful pings mean the tunnel is ready.

Step 4 — Prepare the Website on VPS-2

Create the website in aaPanel or your web server using its real domain, for example shop.example.com. The web server must listen on 10.10.10.2:80 or 0.0.0.0:80.

If UFW is active on VPS-2, allow VPS-1 to reach the website through WireGuard:

sudo ufw allow in on wg0 from 10.10.10.1 to any port 80 proto tcp

Test the website from VPS-1 before creating the reverse proxy:

curl -I -H 'Host: shop.example.com' http://10.10.10.2:80

The response should normally be HTTP 200, 301, or 302. Public SSL is installed on VPS-1; the private HTTP hop is already encrypted by WireGuard.

Step 5 — Add DNS, Reverse Proxy, and SSL

  1. Create an A record for shop.example.com pointing to the public IPv4 address of VPS-1.
  2. Open Dashboard and enter the domain and complete upstream URL.
  3. Use http://10.10.10.2:80 as the upstream.
  4. After DNS reaches VPS-1, select Issue SSL.
  5. When Cloudflare is used, select Full (Strict) after the VPS-1 certificate is active.
curl -I https://shop.example.com
sudo rpctl ssl status shop.example.com

The SSL timer checks certificates every day and acme.sh renews them before expiration when DNS and port 80 remain reachable.

Add VPS-3 Through VPS-N

1. Create One Peer for the New Server

On VPS-1, use Dashboard → WireGuard peers - Add a device → Create peer, terminal menu item 13, or this command:

sudo rpctl wg peer add
sudo rpctl wg peer list

The first additional peer is normally client2 with 10.10.10.3/32. Download it from Dashboard or copy this file:

/etc/rpctl/wireguard/peers/client2.conf

2. Install It on VPS-3

Copy the file to /root/client2.conf on VPS-3, then run:

sudo apt update
sudo apt install -y --no-install-recommends wireguard-tools
sudo install -d -m 700 /etc/wireguard
sudo install -m 600 /root/client2.conf /etc/wireguard/wg0.conf
sudo systemctl enable --now wg-quick@wg0
sudo rm -f /root/client2.conf
ip address show wg0
sudo wg show
ping -c 4 10.10.10.1

3. Test from VPS-1 and Add the Website

ping -c 4 10.10.10.3
curl -I -H 'Host: api.example.com' http://10.10.10.3:80

Use http://10.10.10.3:80 as the upstream. Repeat these steps once per additional server. Deleted addresses may be reused, so always check rpctl wg peer list instead of guessing an address.

VPS-2 · client110.10.10.2
VPS-3 · client210.10.10.3
VPS-4 · client310.10.10.4

Connect a Windows Computer

  1. Install the official WireGuard client from wireguard.com/install.
  2. Create a dedicated peer on VPS-1, for example sudo rpctl wg peer add windows-laptop.
  3. Download windows-laptop.conf from Dashboard.
  4. Open WireGuard on Windows and select Import tunnel(s) from file.
  5. Select the downloaded file and activate the tunnel.
  6. Open PowerShell and run ping 10.10.10.1.

On VPS-1, run sudo wg show and confirm that the Windows peer has a recent handshake.

Connect an iPhone, iPad, or Android Device

  1. Install the official WireGuard app from the Apple App Store or Google Play through wireguard.com/install.
  2. Create a separate peer for each device, such as iphone-nam or android-phone.
  3. In the WireGuard app, add a tunnel from a QR code. On the Dashboard, select View QR for that peer and scan the code in the popup. You can alternatively download and import the peer's .conf file.
  4. Activate the tunnel, then check sudo wg show on VPS-1 for a recent handshake.
  5. Open a known private website or service through its 10.10.10.x address to test access.

The QR code and downloaded configuration both contain the peer's private key. Do not capture, share, or reuse either one on another device. Delete downloaded configuration files after importing them.

Private mode routes only 10.10.10.0/24 through WireGuard, so normal Internet traffic continues to use the device's regular connection.

Common Problems

  • No handshake: allow UDP 51820 on the VPS provider firewall and confirm that the client endpoint uses the public IP of VPS-1.
  • Ping works but the website does not: check the origin web server, its listening address, port, UFW rule, and domain virtual host.
  • 502 Bad Gateway: VPS-1 cannot reach the configured upstream.
  • 522 Connection timed out: Cloudflare cannot reach TCP ports 80 or 443 on VPS-1.
  • SSL cannot renew: keep DNS pointed to VPS-1 and public port 80 reachable for the HTTP-01 challenge.
  • Web Panel login blocked: use menu item 11 in sudo rp to unblock the client IP.
